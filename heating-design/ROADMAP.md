# Дорожная карта скилла heating-design

Состояние на 0.8.0-beta (04.08.2026). Отмечает, что уже реализовано, что осталось
из прежних планов и что добавить для более точного и эффективного проектирования.

## Осталось из прежних планов

- Раскладка ТП по произвольному полигону (сейчас `spiral.py` — прямоугольники).
- Автосборка спецификаций из `layer.json` и карточек оборудования.
- Радиаторное/двухтрубное отопление: подбор приборов по каталогу и увязка.
- Библиотека узлов обвязки для марки ТМ.
- Полная марка ВК/К (сейчас только принципиальные решения).
- Автоматизация Revit (сейчас только подготовка данных).

## Планируемые улучшения

Сгруппированы по цели. Приоритет: P1 — ближайшее, даёт наибольший эффект;
P2 — среднее; P3 — по мере надобности.

### A. Инженерная точность расчёта

- **P1. Единый проектный файл `project.json`.** Один источник данных (геометрия,
  конструкции, помещения, оборудование), из которого гонятся все скрипты —
  теплопотери, раскладка, гидравлика, схема, спецификация. Сейчас данные
  дублируются по отдельным JSON и расходятся при правках. Даёт сквозную
  согласованность и убирает ручной перенос чисел.
- **P1. Двухтрубное радиаторное отопление.** Подбор радиаторов/конвекторов по
  каталогу с пересчётом мощности на фактический график по ΔTлог; гидравлика
  двухтрубной сети (тупиковая/попутная), увязка ветвей и подбор настроек
  балансировочных клапанов (Kv). Сейчас догрев считается вручную.
- **P1. Гидравлика всей сети, не только петель ТП.** Магистрали, стояки, ветки
  с увязкой; расширить `hydro.py` на дерево трубопроводов, а не один коллектор.
- **P2. Инфильтрация по СП 50/СП 60 отдельно от вентиляции.** Расчёт через
  щелевую воздухопроницаемость окон/дверей и скоростной напор ветра; сейчас
  `heatloss.py` считает только организованный воздухообмен.
- **P2. Влажностный режim конструкций (точка росы, конденсация).** Проверка
  ограждений по СП 50 на выпадение конденсата в толще — важно для узлов
  примыканий и вентфасадов.
- **P2. Скрипты подбора: бойлер ГВС (объём, время нагрева, пиковый расход) и
  расширительный бак/подпитка.** Методики есть в `kotelnaya.md` — вынести в
  расчётные скрипты, чтобы не считать вручную.
- **P3. Подбор конкретной модели насоса по каталожным кривым** по точке Q×H
  из `hydro.py` (Grundfos/Wilo), а не только рабочая точка.
- **P3. Раскладка ТП по произвольному полигону** (обход колонн, эркеров) вместо
  разбиения на прямоугольники.

### B. Выпуск документации

- **P1. Сборщик комплекта `komplekt.py`.** Автоматическая сборка альбома ОВ:
  титул, общие данные, планы, узлы, схема, спецификации — в один PDF с рамками
  и сквозной нумерацией. На каждом проекте этот сборщик пишется заново — прямой
  кандидат в бандл.
- **P1. Генератор спецификаций `spec.py`.** Сборка ведомостей и спецификаций
  (оборудование, материалы ТП, расходники, ведомость приборов) из карточек и
  `layer.json` по формам ГОСТ 21.110; сейчас спецификации ведутся руками.
- **P2. Генератор общих данных.** Ведомость рабочих чертежей, нормативная база,
  общие указания, указания по монтажу и испытаниям, условные обозначения —
  из проекта, а не копированием.
- **P2. Библиотека УГО (условных обозначений) по ГОСТ 21.205.** Единый модуль
  символов для планов, схем и легенд (арматура, приборы, оборудование), чтобы
  `sheet_pdf.py`/`isometry.py` рисовали по одной библиотеке.
- **P2. Модуль штампа/рамки как отдельный переиспользуемый компонент** (сейчас
  `draw_stamp`/`draw_frame` внутри `sheet_pdf.py`) — чтобы им пользовались и
  схема, и узлы, и спецификации.
- **P3. Автопостроение изометрии из планов ОВ** (сейчас `isometry.py` рисует по
  заданной вручную 3D-схеме) — трассировка стояков и подводок по планам.
- **P3. Экспорт IFC** для обмена BIM, не только Revit-семейства.

### C. Процесс и контроль качества

- **P1. Сквозной кросс-контроль согласованности.** Автоматическая сверка, что
  площади, мощности, длины и марки совпадают между планом, ведомостью,
  спецификацией и схемой; расхождения — в отчёт. Это прямое продолжение блоков
  самопроверки `heatloss.py`.
- **P2. Автоматический нормоконтроль-чеклист** по ГОСТ/СП (состав листов, формы
  надписей, обязательные указания, диаметры и отметки на схеме).
- **P2. Ведение ревизий и таблица изменений** между версиями проекта (что и на
  сколько ватт/метров изменилось) — сейчас ведётся вручную в записке.

### D. Данные и каталоги

- **P1. Машиночитаемая база λ материалов и типовых конструкций** (JSON) — сейчас
  в таблицах `teplotehnika.md`; чтобы `heatloss.py` брал R по имени конструкции.
- **P2. Машиночитаемые каталоги оборудования** (радиаторы, конвекторы, котлы,
  насосы, трубы) для автоподбора и генерации спецификаций.
- **P2. Таблица климата по СП 131.13330** (tн, tот, zот по городам) в JSON —
  чтобы климат подставлялся по названию населённого пункта, а не вручную.

## Принципы, которые сохранять при развитии

- Каждое число имеет адрес (лист АР, пункт СП или расчёт из адресуемого числа).
- Расчёт — скриптом с блоком самопроверки, а не в уме.
- Оформление строго по ГОСТ; данные обезличены (без имён объектов и лиц).
- Правила по трубе ТП (PE-Xa 16×2,0, Dвн 12; Ø20 только уличное; магистраль
  Dвн ≥ 25) и по насосным группам (каждый этаж отдельно) — не менять без причины.
