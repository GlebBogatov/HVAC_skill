# Единый проектный файл project.json

Один файл — один источник данных для всего расчёта. Из него `scripts/project.py`
считает теплопотери, гидравлику и строит схему, а также сквозно проверяет
согласованность. Смысл: числа не дублируются по разным JSON и не расходятся
при правках. В частности, **мощности петель ТП берутся из посчитанных
теплопотерь**, а не вводятся руками второй раз.

## Зачем это

Раньше каждый инструмент имел свой вход (`project_template.json` для heatloss,
`hydro_template.json` для hydro, `shema_template.json` для isometry). При изменении,
например, площади помещения приходилось править числа в нескольких местах, и они
расходились — типовой источник ошибок. Единый файл убирает это: правится один раз,
остальное пересчитывается.

Существующие скрипты не переписаны. `project.py` извлекает нужный срез и вызывает
их как библиотеки — поведение heatloss/hydro/isometry, уже проверенное, сохраняется.

## Команды

```bash
python3 scripts/project.py project.json --check          # сквозная проверка
python3 scripts/project.py project.json --run --outdir out/   # весь конвейер
python3 scripts/project.py project.json --emit heatloss  # вход для одного инструмента
python3 scripts/project.py project.json --emit hydro
python3 scripts/project.py project.json --emit isometry
```

`--run` кладёт в `outdir`: `teplopoteri.md`, `gidravlika.md`, `shema.svg`,
`shema_layer.json`. `--check` возвращает код 1, если есть замечания (годится для
блокировки выпуска до устранения).

## Структура файла

```json
{
  "meta":    {"object": "...", "code": "2025-014", "stage": "Р", "designer": "", "date": ""},
  "climate": {"t_out": -27, "t_ot": -4.7, "z_ot": 196, "city": "..."},
  "building_group": 2,
  "constructions": { "НС-1": {"kind": "wall", "layers": [[0.19,0.47],[0.10,0.042]], "R_se": 0.115} },
  "rooms": [
    {"name": "Кладовая", "area": 18.37, "height": 2.27, "t_in": 16,
     "envelopes": [ ... ], "ground": { ... }, "vent": {"mode": "ach", "value": 0.5}}
  ],
  "tp": {
    "collectors": [
      {"name": "НСУ-1 ...", "t_mean": 38.5, "d_loop_mm": 12.0, "dt": 5.0,
       "kvs_flowmeter": 2.0, "kvs_manifold": 12.0, "kvs_valve": 4.0,
       "fitting": {"d_mm": 20.0, "zeta": 10.0},
       "loops": [
         {"name": "К1", "room": "Кладовая", "length_m": 50.2, "share": 0.5},
         {"name": "К6", "room": "Котельная", "length_m": 14.0}
       ]}
    ]
  },
  "schema": { "nodes": {...}, "pipes": [...], "elements": [...] }
}
```

Блоки `constructions` и `rooms` — как в `references/teplopoteri.md` (heatloss).
Блок `tp.collectors` — как в `references/teplyj-pol.md` § 8 (hydro), но у петли
вместо `Q_W` указывают привязку к помещению:

- `share` — доля мощности помещения на эту петлю (сумма долей по помещению = 1,0);
- без `share`, но с `room` — мощность помещения делится поровну между его петлями;
- `Q_W` (явное значение) — если нужно переопределить.

Блок `schema` — как в `references/izometriya.md` (isometry).

Шаблон целиком — `assets/project_full_template.json`.

## Что проверяет --check

| Проверка | Замечание, если |
|---|---|
| Заполнены meta.object и meta.code | пусто |
| Все конструкции помещений описаны | ссылка на несуществующую конструкцию |
| Теплопотери считаются, баланс сходится | падение расчёта или расхождение баланса |
| Марки петель уникальны по объекту | повтор марки (важно: марка = имя системы в BIM) |
| Петли покрывают мощность помещения | сумма долей ≠ полной нагрузке (>5 %) — недогрев или ошибка долей |
| Узлы труб и элементов схемы существуют | ссылка на несуществующий узел |

Проверка покрытия мощности — прямое следствие правила о догреве малых полей
(см. `teplyj-pol.md`): если петли санузла покрывают меньше нагрузки, `--check`
это покажет, и дефицит надо закрыть прибором.

## Порядок работы с единым файлом

1. Собрать `project.json` из исходных данных АР (meta, климат, конструкции, помещения).
2. `--check` — убедиться, что теплопотери считаются и баланс сходится.
3. Разложить петли (`spiral.py`), внести коллекторы и петли в блок `tp` с привязкой
   к помещениям и долями.
4. Добавить схему (узлы/трубы/элементы) в блок `schema`.
5. `--run` — получить теплопотери, гидравлику и схему из одного источника;
   повторный `--check` перед выпуском.
