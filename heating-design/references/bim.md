# Подготовка к BIM

Раздел на вырост: проект пока выпускается 2D (PDF + DXF), но переход на
информационное моделирование планируется. Смысл этого файла — чтобы миграция
не потребовала переделывать уже сделанное. Всё, что здесь описано, применимо
сегодня и ничего не ломает в текущем процессе.

Главная мысль: **BIM ломается не на геометрии, а на атрибутах.** Нарисовать
трубу в Revit несложно. Сложно, чтобы она попала в спецификацию с правильным
наименованием, артикулом и единицей измерения. Поэтому готовиться нужно
с карточек позиций, а не с моделирования.

## 1. Что уже готово у производителя

VALTEC ведёт библиотеку моделей — раздел
[«Чертежи и модели»](https://valtec.ru/document/technical/techdoc/cherteji_i_shemy_dwg.html).
Таблица по позициям устроена так: серия — название — DWG 2D — PDF 2D —
**BIM REVIT** — STP 3D.

| Что | Как забрать |
|---|---|
| Модель одной позиции | по серии: `https://valtec.ru/document/technical/drawing/<СЕРИЯ>/Revit.zip` — например `V1620` для металлопластиковой трубы 16×2,0 |
| Вся библиотека Revit | архив «ТИМ REVIT» `Rfa.zip`, около 890 МБ |
| Чертежи DWG | архив `Dwg.zip`, около 2,5 ГБ |
| 3D-модели | архив `Stp.zip`, около 3,6 ГБ |
| Шаблон для аксиальных фитингов | отдельный архив на той же странице |

Семейства VALTEC соответствуют требованиям BIM 2.0 и содержат общие параметры
из **ФОП2021 для ADSK-шаблонов** — то есть корректно заносятся в спецификации
проектов, созданных на ADSK-шаблонах. В архивах лежит инструкция по применению
в PDF. Об обновлениях линейки VALTEC пишет в
[новостях](https://valtec.ru/news/).

Сторонние бренды (котлы, бойлеры, насосы, автоматика) моделей у дистрибьюторов
не имеют — их ищут у производителя оборудования либо в агрегаторах BIM-библиотек.
Если модели нет, позиция вносится как обобщённое семейство с правильными
атрибутами: спецификация важнее геометрии.

## 2. Среда проектирования

| Компонент | Что это |
|---|---|
| **ADSK-шаблоны** | шаблоны проекта Autodesk по BIM-стандарту, в том числе для раздела ОВ и ВК |
| **ФОП2021** | файл общих параметров, актуальная редакция; единый ФОП у проектировщиков и производителей — то, что делает обмен моделями возможным |
| Руководство по ADSK-шаблонам | [manual2021.bim2b.ru](https://manual2021.bim2b.ru/) — разбор шаблонов по разделам |

В папке ФОП обычно лежат `ФОП2019.txt` и `ФОП2021.txt` — брать 2021.
Перед стартом проекта проверить, какую редакцию требует заказчик: это первый
вопрос, который снимает половину проблем со спецификациями.

## 3. Нормативная база

- **СП 333.1325800.2020** «Информационное моделирование в строительстве. Правила
  формирования информационной модели объектов на различных стадиях жизненного
  цикла» — [Минстрой России](https://minstroyrf.gov.ru/docs/16405/). Действует
  с 01.07.2021, заменил редакцию 2017 года.
- Требования конкретного проекта задаются заданием заказчика на информационное
  моделирование (EIR) и планом реализации (BEP). **Без них моделировать нельзя** —
  неизвестен состав атрибутов, уровень проработки и формат сдачи, а переделка
  атрибутивного состава на готовой модели стоит дороже, чем сама модель.

Что вытащить из EIR/BEP до начала работы:

| Вопрос | Почему критично |
|---|---|
| Формат сдачи: RVT, IFC4, NWC | определяет весь пайплайн |
| Редакция ФОП и шаблон | иначе спецификации не соберутся |
| Уровень проработки по элементам | определяет трудоёмкость в разы |
| Правила именования систем и элементов | переименование постфактум ломает спецификации |
| Классификатор (КСИ или собственный) | атрибут проставляется при создании, не потом |
| Требования к коллизиям и допуски | определяет, что считать ошибкой |

## 4. Мост из текущего процесса

Текущие DXF-слои раскладываются на категории Revit почти один в один — это не
случайность, слои так и задумывались.

| Слой DXF | Категория / система в модели |
|---|---|
| `TP-<петля>` | Трубопроводы, система напольного отопления, отдельная система на петлю |
| `TP-SUPPLY` | Трубопроводы, те же системы (подводки — часть петли) |
| `HEAT-MAINS-T1` / `T2` | Трубопроводы, система подачи / обратки |
| `EQUIPMENT` | Оборудование, Сантехнические приборы |
| `RISER` | Трубопроводы (вертикальные участки), проёмы через перекрытие |
| `SLEEVE` | Обобщённые модели — гильзы, задания на отверстия |
| `ROOMS` | Помещения (берутся из связанной модели АР, не создаются заново) |
| `AXES` | Оси из связанной модели АР |

Практическое следствие: **имя петли — это имя системы**. Марка `К1`, заведённая
сегодня в `layer.json` и в ведомости, завтра становится именем системы в модели,
и ведомость петель собирается сама. Поэтому марки должны быть уникальны
по всему объекту, а не по этажу.

Геометрия петель из `spiral.py` — это полилиния в модельных миллиметрах
с началом координат на пересечении крайних осей. Та же система координат
используется при связывании моделей, поэтому **начало координат фиксируется
в записке и не меняется между разделами**. Смена начала координат в середине
проекта — самая дорогая ошибка при переходе на BIM.

## 5. Атрибуты позиции

Блок `bim` карточки позиции (`assets/equipment_item.json`) заполняется так,
чтобы значения переносились в параметры семейства без правки:

| Поле карточки | Параметр ADSK (типовой набор) | Замечание |
|---|---|---|
| `name` | ADSK_Наименование | как в спецификации |
| `article` | ADSK_Обозначение / ADSK_Код изделия | артикул производителя |
| `manufacturer` | ADSK_Изготовитель | |
| `unit` | ADSK_Единица измерения | шт., м, компл. |
| `qty` | ADSK_Количество | в модели считается сама |
| `weight_kg` | ADSK_Масса | нужна для нагрузок |
| `note` | ADSK_Примечание | |
| `group` | ADSK_Группирование | порядок в спецификации |

Имена параметров даны как типовой набор — **сверять с фактическим `ФОП2021.txt`
проекта**, состав от редакции к редакции меняется, а параметр с чуть другим
именем в спецификацию не попадёт и будет молча пустым.

Дополнительно в модели пригодятся поля, которых нет в 2D-спецификации:
присоединение (`connection`), Kv (`kv`), габариты (`dimensions`), рабочие
давление и температура (`pn`, `t_max`). Они уже собираются в карточке — именно
поэтому карточка ведётся сейчас, а не «когда перейдём».

## 6. Что делать уже сегодня

1. Вести карточки позиций в `assets/equipment_item.json` — по одной на каждую
   позицию спецификации, с обеими ссылками и датой проверки.
2. Скачать библиотеку VALTEC (`Rfa.zip`) и держать локально: на её обновление
   уходит время, а в момент старта проекта его нет.
3. Марки петель и систем делать уникальными по объекту.
4. Начало координат фиксировать один раз и писать в записке.
5. Толщины стяжки, отметки и высоты вести в модельных миллиметрах —
   не в «примерно 54 мм».
6. Запросить у заказчика EIR/BEP заранее, даже если проект пока 2D: ответ
   «требований нет» тоже результат, его надо зафиксировать письменно.

## 7. Чего не делать

- Не моделировать «в стол» без EIR: атрибутивный состав почти наверняка
  окажется не тем.
- Не считать модель заменой расчёту. Revit не считает теплопотери по СП 50 —
  расчёт остаётся за `heatloss.py` и запиской, модель забирает результат.
- Не создавать помещения и оси в модели ОВ: они приходят связью из АР.
  Дубликаты расходятся при первой же правке архитектора.
- Не подменять артикул производителя артикулом магазина — в модели он остаётся
  навсегда и уезжает в эксплуатацию.
