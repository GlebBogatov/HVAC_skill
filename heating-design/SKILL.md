# Проектирование отопления

Скилл воспроизводит рабочий цикл инженера-проектировщика ОВ: от чтения
архитектурного альбома до выпуска листов. Он не заменяет инженерное решение —
он не даёт забыть шаг, потерять источник числа и выпустить непроверенный расчёт.

Главная идея: **каждое число в записке должно иметь адрес** — либо лист АР,
либо пункт СП, либо расчёт из числа, у которого адрес уже есть. Если адреса нет,
число объявляется допущением и попадает в раздел открытых вопросов.

## Порядок работы

Этапы идут строго по порядку — каждый следующий питается результатами предыдущего.
Не перескакивать к чертежам, пока не сойдётся баланс: перечерчивать дороже, чем пересчитывать.

1. **Исходные данные** — разобрать АР, вытащить геометрию и составы
2. **Теплотехника** — R ограждений, проверка по ГСОП
3. **Теплопотери** — по помещениям, с самопроверкой
4. **Отопительные приборы** — тёплый пол, догрев, увязка
5. **Котельная** — котёл, бойлер, расширительный бак, защита теплообменника
6. **Записка** — расчётно-пояснительная, с разделом контроля
7. **Чертежи** — планы на подложке АР, узлы, спецификации, DXF
8. **Оборудование** — подбор по каталогам, карточки позиций, задел под BIM

## Единый проектный файл (рекомендуемый вход)

Все данные проекта держать в одном `project.json` (объект, климат, конструкции,
помещения, коллекторы и петли ТП, схема). Из него `scripts/project.py` считает
теплопотери, гидравлику и строит схему и сквозно проверяет согласованность —
числа не дублируются и не расходятся при правках. **Мощности петель берутся из
посчитанных теплопотерь**, а не вводятся повторно.

```bash
python3 scripts/project.py project.json --check          # проверка согласованности
python3 scripts/project.py project.json --run --outdir out/   # весь конвейер
```

`--check` ловит: не описанную конструкцию, расхождение баланса, повтор марки
петли, недопокрытие мощности помещения петлями, битую ссылку в схеме; возвращает
код 1 при замечаниях. Шаблон — `assets/project_full_template.json`, формат и
проверки — `references/proekt-fajl.md`. Отдельные шаблоны инструментов
(`project_template.json`, `hydro_template.json`, `shema_template.json`) остаются
для точечных прогонов, но рабочий источник — единый файл.

## 1. Исходные данные

Прежде чем считать, собрать таблицу «что известно / откуда / чего не хватает».
Заказчик редко присылает полный комплект, и половина ошибок в проектах ОВ
рождается из молча принятого допущения.

**Что вытащить из архитектурного проекта** (для каждого пункта записать номер листа):

| Данные | Обычно на листе |
|---|---|
| Площади, экспликация, планировка | планы этажей |
| Длины наружных стен по помещениям | планы этажей |
| Отметки пола, земли, перекрытий, конька | разрез |
| Составы стен, кровли, полов (толщины, материалы) | узлы, «состав полов» |
| Размеры и количество проёмов | планы + фасады + ведомость проёмов |
| Дымоход, приточный воздуховод, окно котельной | план + ведомость |
| Обмерочные размеры существующих проёмов | обмерочный чертёж |

**Что придётся принять самому** (и обязательно вынести в открытые вопросы):
климат по СП 131.13330.2020, λ материалов по СП 50 прил. Т, формула стеклопакета,
кратности воздухообмена, ориентация по сторонам света, температуры смежных
неотапливаемых объёмов.

**Приём для контроля площади остекления.** Посчитать проёмы дважды: по геометрии
плана/фасада и как «площадь наружной поверхности стен минус площадь облицовки
по ведомости отделки фасадов». Расхождение больше 3 % означает, что где-то
потеряно окно или неверно принята высота витража.

Подробности разбора PDF/DXF и калибровки масштаба — `references/ishodnye-dannye.md`.

## 2. Теплотехнический расчёт

R₀ = Rsi + Σ(δ/λ) + Rse, где Rsi = 1/8,7 = 0,115, Rse = 1/23 = 0,043.
Вентилируемый фасад: слои снаружи от вентзазора в расчёт не входят,
вместо Rse принимается 0,115.

Проверка по СП 50.13330.2012: ГСОП = (tв − tот)·zот, далее Rтр = a·ГСОП + b.
Если Rфакт < Rтр — это не повод останавливаться, а повод записать в открытые
вопросы и посчитать теплопотери по факту.

Заглублённые конструкции и полы по грунту считаются **методом зон**, а не через U —
подробности и коэффициенты в `references/teplotehnika.md` вместе с таблицей λ.

## 3. Расчёт теплопотерь

Q = Qтрансм + Qвент + Qинфильтр − Qтеплопоступления.

Считать **скриптом, а не в уме**: `scripts/heatloss.py` принимает JSON с
помещениями и конструкциями и выдаёт таблицу по помещениям, разбивку по
конструкциям и блок самопроверки. Вручную в таблице легко потерять надбавку
на одном помещении из десяти и не заметить.

```bash
python3 scripts/heatloss.py project.json --md > teplopoteri.md
python3 scripts/heatloss.py project.json --json > teplopoteri.json
```

Шаблон входного файла — `assets/project_template.json`, описание всех полей и
методика (надбавки β, врывание через двери, вентиляция, коэффициенты n) —
`references/teplopoteri.md`.

**Обязательный блок самопроверки.** Скрипт печатает его сам, но результат нужно
прочитать глазами и вынести в записку:

- замыкание периметра здания по осям;
- сумма площадей зон грунта = геометрическая площадь пола (расхождение < 0,5 %);
- площади помещений: геометрия против экспликации АР;
- остекление: геометрия против ведомости отделки фасадов;
- замыкание теплового баланса (сумма по помещениям = сумма по конструкциям);
- Rфакт против Rтр по каждой конструкции.

Расхождение — это не ошибка, которую надо спрятать, а информация. Если площадь
коридора по DXF на 0,6 м² больше, чем по экспликации, скорее всего архитектор
исключил проём лестницы; это надо написать, а не подогнать.

**Если считаете повторно** — обязательно приложить таблицу «что изменилось и на
сколько ватт». Заказчик и эксперт спрашивают именно это, а восстановить дельту
задним числом почти невозможно.

## 4. Отопительные приборы

### Тёплый пол

Теплосъём с поверхности: q = 8,92·(tпов − tв)^1,1 Вт/м².
Предел температуры поверхности (СП 60.13330.2020 п. 6.4.9): 26 °C в зонах
постоянного пребывания, 31 °C в санузлах, 35 °C над отопительными трубами.

Порядок: посчитать требуемый qтреб = Qпом/Aтп → найти нужную tпов → сравнить с
пределом. Если упирается в предел — **это не повод завышать температуру**,
а сигнал, что нужен догрев конвекторами или радиаторами. В зале с панорамным
остеклением такое происходит почти всегда.

**Труба контуров ТП — PE-Xa 16×2,0 (Dвн 12,0 мм)**, стандартный бытовой
типоразмер; кислородный барьер EVOH обязателен. PE-Xb, PE-RT и металлопластик
в петлях не применять. Труба Ø20 (20×2,0, Dвн 16) во внутрипольные петли **не
идёт** — она резервируется под уличное отопление (обогрев площадок, пандусов,
кровель, водостоков). Три следствия для Dвн 12, которые нельзя забыть: стяжка
≥ 61 мм над утеплителем (≥ 45 мм над трубой Ø16), объём системы 0,113 л/м и
нижний порог расхода — петля меньше ≈ 350 Вт при Δt = 5 К даёт скорость ниже
0,15 м/с и завоздушивается.

Раскладка — **улитка (встречная спираль)**, а не змейка: подача и обратка
чередуются через нитку, поверхность прогревается равномерно, радиус гиба вдвое
больше — для PE-Xa Ø16 минимальный радиус 5·Dн = 80 мм, шаг улитки менее 80 мм
не задавать.

```bash
python3 scripts/spiral.py --w 3400 --h 2280 --step 150 --offset 150 --json loop.json
```

Скрипт выдаёт полилинию, длину петли и контроль по L ≈ A/s. Подводки от петли
до коллектора считаются отдельно и **обязательно включаются в длину** — про них
забывают, а на дальней петле это 10–12 м.

Ограничения: длина петли с подводками ≤ 100 м (рабочий ориентир — 75 м), шаг
150 мм у наружных стен и витражей, 200–250 мм в глубине, менее 80 мм не задавать
(радиус гиба), отступ от наружных стен 150 мм.

**Поле петли не проводить под несущими стенами** (труба в стяжке — не
отремонтировать; отступ ≥ 150 мм, обходить лестницы и колонны). Подводки стены
пересекать можно, в гильзе. Открытый зал без внутренних стен из-за этого не
ужимать. После любой перекладки петель пересчитывать заново и площади (дефицит
малых полей), и длины (гидравлику).

### Гидравлика и подбор насоса

Потери по петлям, индексную (самую неблагоприятную) петлю и рабочую точку
насосно-смесительного узла считать скриптом — вручную индексную петлю легко
назначить не ту, а после перекладки напор меняется:

```bash
python3 scripts/hydro.py collectors.json --md > gidravlika.md
```

Вход — `assets/hydro_template.json` (длины из spiral.py, мощности из heatloss.py).
Скрипт по Колбруку выдаёт Δp каждой петли, ловит малые петли (v < 0,15 м/с),
находит индексную и собирает рабочую точку насоса Q × H по её пути, а по ней
подбирает модель насоса по встроенному рабочему полю кривых (WILO Star RS /
Grundfos UPS). Насос — Δp-c. Состав узлов — `references/uzly.md`.

### Догрев и приборы

Дефицит основной площади закрывается конвекторами вдоль остеклённых фасадов.
Проверить, что выбранный тип физически помещается: внутрипольный конвектор
требует ≥ 100 мм чистой глубины — в стяжке 65 мм по ЭППС 20 мм он не встанет.
Малые мокрые помещения (санузел) добирать электрическим полотенцесушителем или
матом под плитку, проходной коридор — считать транзитной зоной (tпов до 31 °C).

Формулы, шаги, раскладка, гидравлика и догрев — `references/teplyj-pol.md`.

## 5. Котельная

Порядок подбора: котёл → бойлер → расширительный бак → защита теплообменника →
группы безопасности и подпитка.

- **Котёл** — по расчётной нагрузке с запасом 10 %; загрузка 60–80 % в расчётном
  режиме оставляет резерв на приоритет ГВС.
- **Бойлер** — по наличию душевой: без душа 80–100 л, с душем 150–200 л. Проверить
  время нагрева и запас смешанной воды 40 °C.
- **Расширительный бак** — Vб = Vсист·β / (1 − (Pнач+1)/(Pпред+1)).
- **Чугунный теплообменник** — обратка не ниже 50 °C, термостатический
  смесительный клапан на байпасе котла. Это обязательное условие, а не опция:
  низкотемпературная коррозия убивает чугун за несколько сезонов.
- **Котёл и бойлер одного бренда** — штатный датчик NTC подключается напрямую
  к плате, приоритет ГВС без внешнего контроллера.
- **Каждый этаж — своя насосная группа**, раздельно для тёплого пола и для
  радиаторов. Объединение этажей вынуждает вести систему по самому горячему
  потребителю и давить остальных дросселированием. Подробности — в справочнике.
- **Магистраль от коллектора котельной до коллектора ТП — Dвн не менее 25 мм**
  (нерж. 28×1,2, медь 28×1,0, PE-Xa 32×2,9 SDR11, сталь Ду25). Ходовая PE-Xa
  32×4,4 SDR7,4 даёт Dвн 23,2 и **не проходит** — типоразмер проверять по стенке,
  а не по наружному диаметру.

Проверить помещение котельной по СП 402.1325800.2018: объём, площадь остекления
не менее 0,03 м²/м³, дымоход, приток.

Если источник не один (резерв, подхват, пиковый котёл, тепловой насос,
твердотопливный котёл с буфером, каскад) — логика комбинирования, гидравлическая
развязка, подбор буфера и требования к твердотопливной котельной в
`references/istochniki-i-toplivo.md`. Там же теплотворность топлива, КПД, COP
и оценка годовых затрат для выбора источника.

Расчёты, схемы обвязки и номенклатура — `references/kotelnaya.md` и
`references/oborudovanie.md`.

## 6. Расчётно-пояснительная записка

Формат — markdown, структура фиксированная (шаблон в `assets/pz_template.md`):

1. Исходные данные (нормативная база, климат, температуры, теплоноситель)
2. Теплотехнический расчёт ограждающих конструкций
3. Расчёт теплопотерь
4. Напольное отопление
5. Оборудование котельной
6. Водоснабжение и канализация (если в объёме работ)
7. Вопросы, требующие решения
7а. **Контроль расчёта**
8. Состав выпускаемой документации

Раздел «Контроль расчёта» — не формальность. Он превращает записку из набора
чисел в проверяемый документ и первым читается экспертом.

Раздел «Вопросы, требующие решения» ведётся таблицей с колонкой «Статус»
(Открыт / Принято / Согласовано с датой). Согласование заказчика фиксируется
датой прямо в таблице — потом это единственный след договорённости.

## 7. Чертежи

Планы выпускаются **наложением слоя ОВ на страницы архитектурного PDF**, а не
перечерчиванием: петли садятся на реальные стены, а не на реконструкцию геометрии.

Порядок:

1. Снять с листа АР координаты двух марок осей в точках PDF → получить масштаб pt/мм.
2. Проверить сходимость по всем остальным пролётам осей — должна быть лучше 0,1 %.
   Если хуже, лист неравномерно отмасштабирован, накладывать нельзя.
3. Нарисовать слой ОВ в модельных координатах (мм), скрипт переведёт в точки.

```bash
python3 scripts/sheet_pdf.py --ar AR.pdf --page 5 \
    --calib calib.json --layer ov_cokol.json --out ОВ-05.pdf
python3 scripts/dxf_export.py --layer ov_cokol.json --out ОВ-05.dxf
```

Слои DXF: `TP-<петля>`, `TP-SUPPLY`, `HEAT-MAINS-T1/T2`, `EQUIPMENT`, `RISER`,
`SLEEVE`, `ROOMS`, `AXES`, `TEXT`. Единицы — мм, начало координат на пересечении
крайних осей.

**Аксонометрическая схема системы отопления** (для систем со стояками и
разветвлёнными магистралями) выпускается отдельным листом в косоугольной
фронтальной изометрии (ГОСТ 2.317-2011, ось Y под 45°; состав по ГОСТ 21.602-2016).
Строить скриптом из 3D-схемы, а не рисовать вручную:

```bash
python3 scripts/isometry.py shema.json --svg ОВ-09.svg --layer ОВ-09.json
python3 scripts/dxf_export.py --layer ОВ-09.json --out ОВ-09.dxf
```

`isometry.py` проецирует узлы (x вдоль фронта, y в глубину, z вверх, мм),
рисует Т1/Т2, стояки, коллекторы-гребёнки, насосно-смесительные узлы, приборы,
арматуру, воздухоотводчики, отметки, парные магистрали 2d= и диаметры,
и выдаёт SVG для просмотра плюс layer.json для того же выпуска (DXF, лист с
рамкой). Шаблон — `assets/shema_template.json`, методика и УГО —
`references/izometriya.md`.

**Формат, рамка и основная надпись — по ГОСТ Р 21.101-2020 и ГОСТ 2.301-68:**
рамка сплошной основной линией с полем 20 мм слева и по 5 мм с трёх сторон;
основная надпись листов рабочих чертежей ОВ — форма 3 (185×55 мм) в правом
нижнем углу; спецификации и текстовые листы — формы 5/6; марка комплекта
отопления — ОВ (ГОСТ 21.602-2016). При наложении на подложку АР рамка уже есть;
для самостоятельного листа — `sheet_pdf.py --frame`.

Состав марок О, ТМ, ВК, К, формы основной надписи и правила оформления —
`references/dokumentaciya.md`, детали привязки и условные обозначения —
`references/chertezhi.md`.

## 8. Оборудование и подготовка к BIM

Источники разделены по ролям: **VALTEC** — производитель, у него берутся
технические характеристики, паспорта, чертежи и BIM-модели; **Лунда** и
**Терем** — дистрибьюторы, у них проверяются наличие и цена, а также
подбирается то, чего VALTEC не производит (котлы, бойлеры, насосы, автоматика).

Подбор «по карточке интернет-магазина» регулярно даёт неверный Kv, неверное
присоединение и снятый с производства артикул — поэтому характеристики всегда
от производителя, а в спецификацию идёт артикул производителя, не магазина.

Каждая позиция собирается в машиночитаемую карточку по шаблону
`assets/equipment_item.json` — с обеими ссылками, датой проверки и блоком
BIM-атрибутов. Это не бюрократия: при переходе на информационное моделирование
эти же поля лягут в параметры семейства Revit без переписывания.

Что делать уже сейчас, чтобы миграция не стоила переделки: держать локально
библиотеку семейств VALTEC, делать марки петель уникальными по всему объекту
(марка петли станет именем системы в модели), фиксировать начало координат один
раз и запрашивать у заказчика EIR/BEP заранее. Детали — `references/bim.md`.

## Что скилл сознательно не делает

- Не считает вентиляцию как раздел (только воздухообмен для теплопотерь).
- Не выпускает раздел ВК и К в полном объёме — только принципиальные решения.
- Считает гидравлику петель ТП и подбирает насосы НСУ (`hydro.py`, Колбрук,
  индексная петля), но не заменяет полный гидравлический расчёт разветвлённой
  сети радиаторов и магистралей в специализированном ПО: для коттеджа с
  коллекторами этого достаточно, для многоэтажного объекта — нет.
- Не подбирает оборудование без проверки по актуальному каталогу. Характеристики
  берутся у производителя, наличие — у дистрибьютора, дата проверки пишется
  в карточку позиции. Артикулы и линейки производители меняют примерно раз в год.
- Не моделирует в Revit. Раздел `references/bim.md` — это подготовка к переходу:
  что собирать сейчас, чтобы потом не переделывать.
